# Smerfume Backend — API Design

## Overview

| Property | Value |
|---|---|
| Base path | `/api/` |
| API versioning | None — no version prefix currently |
| Authentication | JWT Bearer token (`Authorization: Bearer <access_token>`) |
| Default pagination | `PageNumberPagination`, page size 24 |
| Content type | `application/json` |
| Schema | OpenAPI 3.0 (auto-generated by `drf-spectacular`) |
| Swagger UI | `/api/docs/` |
| ReDoc | `/api/redoc/` |
| Raw schema | `/api/schema/` |

---

## Conventions

### Public Identifiers

**Internal integer PKs are never returned in API responses.** All resources expose `public_id` (UUID) as their public identifier. The only exception is `CartItem.id` (integer), which is used in cart item update/delete URLs.

### Error Response Format

DRF's default error format is used:

```json
{ "field_name": ["Error message."] }
```

For non-field errors:
```json
{ "error": "Human-readable message." }
```

For unhandled DRF exceptions:
```json
{ "detail": "Message." }
```

### Pagination

Default: `PageNumberPagination` with `page_size=24`. Paginated responses:
```json
{
  "count": 100,
  "next": "http://host/api/catalog/products/?page=2",
  "previous": null,
  "results": [...]
}
```

Catalog ViewSets are paginated. Cart and auth endpoints are not.

### Throttling

| Scope | Rate (prod) | Applied to |
|---|---|---|
| `otp_request` | 5/hour | `POST /api/auth/otp/request/` |
| `otp_verify` | 10/minute | `POST /api/auth/otp/verify/` |
| `anon` | 100/day | All unauthenticated endpoints |
| `user` | 1000/day | All authenticated endpoints |

## Authentication APIs

Base path: `/api/auth/`

---

### `POST /api/auth/otp/request/`

**Purpose:** Send a 6-digit OTP to an Indian mobile number. Creates a new user account if the number is not registered.

**Auth required:** No  
**Permission:** `AllowAny`  
**Throttle scope:** `otp_request` (5/hour in prod)

**Request Body:**

```json
{ "mobile_number": "9876543210" }
```

**Accepted mobile formats:**
- `9876543210` (10-digit)
- `919876543210` (12-digit with country code)
- `+919876543210` (E.164)

First digit must be 6, 7, 8, or 9.

**Serializer:** `RequestOTPSerializer` → normalises to E.164 (`+91XXXXXXXXXX`)

**Response 200:**
```json
{
  "otp_session_token": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "expires_in": 300,
  "resend_available_in": 30
}
```

| Field | Type | Notes |
|---|---|---|
| `otp_session_token` | UUID string | Pass this to `/verify/` and `/resend/`. Does not change on resend. |
| `expires_in` | integer | Seconds until OTP expires (always 300) |
| `resend_available_in` | integer | Seconds until a resend is allowed (0 on first request) |

Optional field when SMS fails:
```json
{ ..., "sms_sent": false }
```

**Always returns 200** — account enumeration prevention (attacker cannot tell if number is registered).

**Response 400:** Invalid mobile number format.  
**Response 429:** Rate limit exceeded.

---

### `POST /api/auth/otp/verify/`

**Purpose:** Submit OTP to verify identity and receive JWT tokens.

**Auth required:** No  
**Permission:** `AllowAny`  
**Throttle scope:** `otp_verify` (10/minute in prod)

**Request Body:**
```json
{
  "otp_session_token": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "otp": "123456"
}
```

**Serializer:** `VerifyOTPSerializer`  
Validation: `otp` must be exactly 6 digits, numeric only.

**Response 200:**
```json
{
  "access": "<jwt_access_token>",
  "refresh": "<jwt_refresh_token>",
  "is_new_user": true,
  "user": {
    "public_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "mobile_number": "+919876543210",
    "email": null,
    "role": "customer",
    "name": ""
  }
}
```

| Field | Notes |
|---|---|
| `access` | JWT access token (60 min in local/UAT, 15 min in prod) |
| `refresh` | JWT refresh token (7 days) |
| `is_new_user` | `true` if account was just created — client should redirect to profile completion |
| `user.public_id` | UUID — use this as the user identifier client-side |
| `user.name` | `first_name + last_name` — empty string until profile is updated |

**Failure modes (all return 400):**

| Error | Condition |
|---|---|
| "Invalid or expired session." | `otp_session_token` not found or `is_active=False` |
| "This OTP has already been used." | `is_verified=True` |
| "OTP has expired." | `now > expires_at` |
| "Too many incorrect attempts." | `attempt_count >= 3` |
| "Incorrect OTP. N attempt(s) remaining." | Wrong OTP; counter incremented |

**Response 429:** Rate limit exceeded.

---

### `POST /api/auth/otp/resend/`

**Purpose:** Generate a new OTP and resend on the same session. `otp_session_token` stays the same.

**Auth required:** No  
**Permission:** `AllowAny`

**Request Body:**
```json
{ "otp_session_token": "3fa85f64-5717-4562-b3fc-2c963f66afa6" }
```

**Serializer:** `ResendOTPSerializer`

**Response 200:**
```json
{
  "detail": "OTP resent successfully.",
  "resend_available_in": 30
}
```

**Failure modes (all return 400):**

| Error | Condition |
|---|---|
| "Invalid or expired session." | Token not found or inactive |
| "This OTP has already been verified." | Session already used |
| "Maximum resend limit reached." | `resend_count >= 3` |
| "Please wait N second(s)..." | Cooldown active (30 seconds between resends) |

---

### `POST /api/auth/token/refresh/`

**Purpose:** Exchange a valid refresh token for a new access token.

**Auth required:** No  
**Permission:** `AllowAny`

**Request Body:**
```json
{ "refresh": "<jwt_refresh_token>" }
```

**Response 200:**
```json
{
  "access": "<new_access_token>",
  "refresh": "<new_refresh_token>"
}
```

With `ROTATE_REFRESH_TOKENS=True`: old refresh token is blacklisted; new refresh token returned. Both `access` and `refresh` are returned.

**Response 401:** Token invalid or blacklisted.

---

### `POST /api/auth/logout/`

**Purpose:** Blacklist the refresh token to invalidate the session.

**Auth required:** Yes (`Authorization: Bearer <access_token>`)  
**Permission:** `IsAuthenticated`

**Request Body:**
```json
{ "refresh": "<jwt_refresh_token>" }
```

**Response 200:**
```json
{ "detail": "Logged out successfully." }
```

**Response 400:** Refresh token missing or already blacklisted.  
**Response 401:** Access token missing or expired.

Note: Access token expires naturally (60 min). There is no server-side revocation for access tokens — only refresh tokens are blacklisted.

---

### `GET /api/auth/me/`

**Purpose:** Return the authenticated user's public profile.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`

**Serializer:** `UserMeSerializer`

**Response 200:**
```json
{
  "public_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "mobile_number": "+919876543210",
  "email": "user@example.com",
  "role": "customer",
  "name": "Rahul Sharma"
}
```

Integer PK is never returned. `email` may be `null` for mobile-only accounts.

**Response 401:** Access token missing or expired.

---

### `PATCH /api/auth/me/`

**Purpose:** Update own profile (intended for profile completion after `is_new_user=true`).

**Auth required:** Yes  
**Permission:** `IsAuthenticated`

**Serializer:** `UpdateMeSerializer`  
**Updatable fields:** `first_name`, `last_name`, `email` (all optional, partial update)

**Request Body:**
```json
{
  "first_name": "Rahul",
  "last_name": "Sharma",
  "email": "rahul@example.com"
}
```

**Validation:**
- `email`: must be unique across all users (excluding current user)
- `mobile_number` and `role` cannot be changed via this endpoint

**Response 200:** Same as `GET /api/auth/me/`  
**Response 400:** Email already taken.  
**Response 401:** Access token missing or expired.

## Catalog APIs

Base path: `/api/catalog/`

All catalog endpoints are public (`AllowAny`). No authentication required.

---

### `GET /api/catalog/products/`

**Purpose:** List all active products with editions and variants.

**Auth required:** No  
**Permission:** `AllowAny`  
**Pagination:** Yes (page size 24)  
**Serializer:** `ProductListSerializer`

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `search` | string | Search by product name, brand name, or edition name. Minimum 2 characters. |
| `brand` | string | Filter by brand slug |
| `category` | string | Filter by category slug |
| `gender` | string | `men` \| `women` \| `unisex` |
| `concentration` | string | `edc` | `edt` | `edp` | `extrait` | `attar` |\| `edt` \| `edp` \| `extrait` |
| `note` | string | Comma-separated note names, AND logic (all notes must appear in the same edition). Max 5 notes. |
| `is_best_seller` | string | `true` \| `false` |
| `is_new_arrival` | string | `true` \| `false` |
| `ordering` | string | `name` \| `-name` \| `brand__name` \| `-brand__name` |

**Filter behaviour:**
- `gender`, `concentration`, `is_best_seller`, `is_new_arrival`, and `note` are edition-level filters. They are applied via subquery on `ProductEdition` to prevent cross-edition contamination.
- `search` requires minimum 2 characters; single-character searches return empty results (not an error).
- Invalid `gender` or `concentration` values return HTTP 400.

**Response 200 (paginated):**
```json
{
  "count": 50,
  "next": "http://host/api/catalog/products/?page=2",
  "previous": null,
  "results": [
    {
      "public_id": "uuid",
      "name": "Baccarat Rouge 540",
      "slug": "baccarat-rouge-540",
      "brand": {
        "public_id": "uuid",
        "name": "Maison Francis Kurkdjian",
        "slug": "mfk",
        "brand_category": "niche"
      },
      "category": {
        "public_id": "uuid",
        "name": "Eau de Parfum",
        "slug": "edp"
      },
      "editions": [
        {
          "public_id": "uuid",
          "name": null,
          "slug": "baccarat-rouge-540-edp",
          "image": "/media/catalog/editions/image.jpg",
          "gender": "unisex",
          "concentration": "edp",
          "is_best_seller": true,
          "is_new_arrival": false,
          "variants": [
            {
              "public_id": "uuid",
              "image": null,
              "size_ml": 70,
              "is_decant": false,
              "mrp": "32000.00",
              "selling_price": "29500.00"
            }
          ]
        }
      ]
    }
  ]
}
```

Both `mrp` and `selling_price` are returned so the frontend can display the original price and savings.

## Cart APIs

Base path: `/api/cart/`

All cart endpoints require authentication.

---

### `GET /api/cart/`

**Purpose:** Return the current user's cart with all items and totals.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**Serializer:** `CartSerializer`

Creates an empty cart if one does not yet exist.

**Response 200:**
```json
{
  "public_id": "uuid",
  "items": [
    {
      "id": 1,
      "variant": {
        "public_id": "uuid",
        "image": null,
        "size_ml": 70,
        "is_decant": false,
        "selling_price": "29500.00"
      },
      "quantity": 2,
      "line_total": "59000.00"
    }
  ],
  "total": "59000.00",
  "item_count": 1
}
```

**Note:** `CartItem.id` (integer) is returned here because it is used as the path parameter in update/delete operations.

**Response 401:** Access token missing or expired.

---

### `POST /api/cart/add/`

**Purpose:** Add a variant to the cart. If already present, quantities are combined (capped at 99).

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**Serializer:** `AddToCartSerializer`

**Request Body:**
```json
{ "variant_id": 1, "quantity": 2 }
```

| Field | Type | Validation |
|---|---|---|
| `variant_id` | integer (PK) | Must be an active `ProductVariant` |
| `quantity` | integer | 1–99, default 1 |

**Response 200:** Full `CartSerializer` response (same as `GET /api/cart/`).  
**Response 400:** Invalid variant or quantity.  
**Response 401:** Access token missing or expired.

---

### `PATCH /api/cart/items/{item_id}/`

**Purpose:** Set a new quantity for a cart line item.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**URL parameter:** `item_id` (integer CartItem PK)  
**Serializer:** `UpdateCartItemSerializer`

**Request Body:**
```json
{ "quantity": 3 }
```

**Validation:** quantity must be 1–99.

**Response 200:** Full `CartSerializer` response.  
**Response 400:** Invalid quantity.  
**Response 401:** Access token missing or expired.  
**Response 404:** Item not found in this user's cart.

---

### `DELETE /api/cart/items/{item_id}/`

**Purpose:** Remove a single line item from the cart.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**URL parameter:** `item_id`

**Response 200:** Full `CartSerializer` response (cart without the removed item).  
**Response 401:** Access token missing or expired.  
**Response 404:** Item not found in this user's cart.

---

### `DELETE /api/cart/clear/`

**Purpose:** Remove all items from the cart.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`

**Response 200:** Full `CartSerializer` response (empty cart).  
**Response 401:** Access token missing or expired.

## Order APIs

Base path: `/api/orders/`

All order endpoints require authentication.

---

### `POST /api/orders/checkout/`

**Purpose:** Convert the authenticated user's cart into an order.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**Serializer:** `CheckoutSerializer`  
**Transaction:** Atomic

**Request Body:**
```json
{
  "shipping_address": {
    "full_name": "Rahul Sharma",
    "mobile": "9876543210",
    "address_line1": "42, MG Road",
    "address_line2": "Near Central Mall",
    "city": "Bengaluru",
    "state": "KA",
    "pincode": "560001",
    "country": "India"
  },
  "customer_notes": "Please pack as a gift."
}
```

**Shipping Address Fields:**

| Field | Required | Validation |
|---|---|---|
| `full_name` | Yes | max 200 chars |
| `mobile` | Yes | 10–15 digits, optional leading `+` |
| `address_line1` | Yes | max 255 chars |
| `address_line2` | No | blank allowed |
| `city` | Yes | max 100 chars |
| `state` | Yes | 2-letter Indian state code (e.g. `KA`, `MH`, `DL`) |
| `pincode` | Yes | exactly 6 digits |
| `country` | No | default "India" |

**Checkout Process (atomic):**
1. Validate shipping address
2. Fetch cart — return 400 if no cart or cart is empty
3. Create `Order` with `status=pending`, `discount_amount=0`
4. Bulk-create `OrderItem` records (prices snapshotted)
5. Create `ShippingAddress`
6. Delete all cart items

**No payment is processed at checkout.** Order is created in `pending` status.

**Response 201:**
```json
{
  "public_id": "uuid",
  "order_number": "SMR-20260819-A3F2B1",
  "status": "pending",
  "channel": "online",
  "payment_method": "cod",
  "subtotal": "29500.00",
  "discount_amount": "0.00",
  "total": "29500.00",
  "customer_notes": "Please pack as a gift.",
  "items": [
    {
      "variant": { "public_id": "uuid", "size_ml": 70, "is_decant": false, "selling_price": "29500.00", "image": null },
      "quantity": 1,
      "unit_price": "29500.00",
      "line_total": "29500.00"
    }
  ],
  "shipping_address": {
    "full_name": "Rahul Sharma",
    "mobile": "9876543210",
    "address_line1": "42, MG Road",
    "address_line2": "Near Central Mall",
    "city": "Bengaluru",
    "state": "KA",
    "pincode": "560001",
    "country": "India"
  },
  "created_at": "2026-08-19T10:00:00Z"
}
```

**Response 400:** Cart is empty, or validation error on shipping address.  
**Response 401:** Access token missing or expired.

---

### `GET /api/orders/`

**Purpose:** Return the authenticated user's order history, newest first.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**Serializer:** `OrderSerializer` (many=True)  
**Pagination:** Yes (default page size 24)

Filters automatically to the current user — no ability to view other users' orders.

**Response 200:** Paginated list of order objects (same structure as checkout response).
In-store purchases made with the customer's mobile number appear here too,
with `channel: "in_store"` and `shipping_address: null`.

---

### `GET /api/orders/{order_number}/`

**Purpose:** Return full detail for a single order.

**Auth required:** Yes  
**Permission:** `IsAuthenticated`  
**URL parameter:** `order_number` (e.g. `SMR-20260819-A3F2B1`)

Filtered to current user — returns 404 if the order number belongs to a different user.

**Response 200:** Full order object (same structure as checkout response).  
**Response 401:** Access token missing or expired.  
**Response 404:** Order not found or not owned by current user.

---

### `POST /api/orders/in-store/`

**Purpose:** Record a walk-in sale made at the shop or warehouse counter (DEC-008).

**Auth required:** Yes
**Permission:** `IsStaffMember` (`role` = `staff` or `admin`)
**Serializer:** `InStoreSaleSerializer` (request), `OrderSerializer` (response)
**Service:** `apps.orders.services.create_in_store_order`
**Transaction:** Atomic. Nothing is created if any line fails.

**Request Body:**
```json
{
  "customer_mobile": "9876543210",
  "customer_name": "Rahul Sharma",
  "items": [
    { "sku": "AAM-AHL-EDP-60", "quantity": 1 },
    { "sku": "AAM-KAAF-DEC-10", "quantity": 2 }
  ],
  "payment_method": "upi",
  "payment_reference": "412345678901",
  "discount_amount": "200.00",
  "warehouse": null,
  "notes": "Gift wrapped at counter."
}
```

| Field | Required | Validation / behaviour |
|---|---|---|
| `customer_mobile` | Yes | 10–15 digits, optional leading `+`. Finds the customer, or creates one silently (same as guest checkout). |
| `customer_name` | No | Used only when a new customer is created. Existing users are never modified. |
| `items` | Yes | At least one `{sku, quantity}`. `quantity` 1–1000. Unknown SKU → 400. Inactive variant → 400. Repeated SKUs are merged. |
| `payment_method` | Yes | `cash`, `upi`, `card` or `netbanking`. `cod`/`prepaid` are rejected. |
| `payment_reference` | No | UPI/netbanking UTR or card slip number. Max 100 chars. |
| `discount_amount` | No | Order-level discount, default `0`. Must be between 0 and the subtotal. Spread across lines proportionally. |
| `warehouse` | No | Warehouse `public_id`. Defaults to the default warehouse. |
| `notes` | No | Stored as `customer_notes`. |

**Process (atomic):**
1. Resolve or create the customer from `customer_mobile`.
2. Price each line at the variant's current `selling_price`; allocate the discount.
3. Create the `Order` (`channel=in_store`, `created_by` = staff user) and its `OrderItem`s.
   No shipping address, shipping surcharge or fees.
4. Reserve and immediately consume stock per line through the inventory reservation
   service (retail bottles, or FIFO partial lots / bottle opening for decants).
5. Mark the order `delivered` with `delivered_at` = now.

**Response 201:** Order object (same structure as checkout), with `"channel": "in_store"`,
`"status": "delivered"` and `"shipping_address": null`.
**Response 400:** Validation error, unknown/inactive SKU, invalid discount, or insufficient stock
(`{"error": "Only 0 unit(s) of ... available at ..., needed 1."}`).
**Response 401:** Access token missing or expired.
**Response 403:** Authenticated user is not staff.

**Returns:** in-store orders cannot be returned through
`POST /api/orders/{order_number}/returns/` (400). Issues are handled at the counter.

The same sale can be recorded in the admin: **Orders → New in-store sale**.

---

## Admin Interface

`/admin/` — Django Admin with Unfold theme. Session-authenticated (not JWT). Available to `is_staff=True` users. Not an API endpoint — browser UI only.

All catalogue management (creating products, editions, variants, brands, etc.) is done through the admin interface.

The generic "Add order" form is disabled. Walk-in counter sales are recorded on
**Orders → New in-store sale** (`/admin/orders/order/in-store-sale/`, requires the
`orders.add_order` permission), which calls the same service as
`POST /api/orders/in-store/`.

### Reviews

- `GET /api/catalog/products/{slug}/reviews/`
- `POST /api/catalog/products/{slug}/reviews/`

### Notifications

- Transactional SMS/email for order confirmation, shipping updates (no API; background task)
